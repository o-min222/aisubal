# Languages (i18n)

AI쓰발 is written in Korean. English is a translation layer on top; more languages plug in the same way.

## How it works

- **Source text is the key.** UI strings stay in Korean in the code and are looked up in a per-language dictionary
  (`src/i18n/dict/en.ts`). A missing entry falls back to Korean, so nothing ever renders blank.
- **Locale = cookie, not URL.** `aisubal_locale` (1 year). No `/en/...` prefixes, so links like `/i/{code}` never change.
  Order: cookie → the member's saved choice (`members.locale`, set via `member_set_locale`) → `Accept-Language` → Korean.
- **Switcher:** account menu (Language row), Settings › Account › Language, and the logged-out landing/login/invite pages.
  `POST /api/locale` sets the cookie and, for members, saves it to the profile.
- **Member content is never translated** (posts, names, tags, tool descriptions, collections).
  The pledge shows an English translation with the Korean original one tap away — the original is authoritative.
- MCP/agent-facing text (`tool-review.ts` descriptions, the charter) stays as authored.

## Marking strings

| Where | Use |
| --- | --- |
| JSX text (server or client) | `<T>저장</T>`, or `<T s="멤버 {n}" vars={{ n }} />` (vars may be JSX) |
| Server component / route | `const t = await getT()` → `t('…')` (from `@/i18n/server`) |
| Client attributes, handlers, toasts | `tx('…')` / `tn('…')` (from `@/i18n/client`) |
| Constants rendered later | `msg('…')` (identity marker) and render with `<T>{label}</T>` |

`tests/i18n.test.ts` scans `src/` for every marked string and fails if a dictionary lacks it or drops a `{placeholder}`.

## Adding a language (e.g. Japanese)

1. `src/i18n/config.ts`: add `'ja'` to `LOCALES` and a `LOCALE_META.ja` entry (`native: '日本語'`, `htmlLang`, `og`, `intl`).
2. Copy `src/i18n/dict/en.ts` to `ja.ts`, translate the values, and register it in `src/i18n/dict/index.ts`.
3. Optionally add a `PLEDGE_JA` translation in `src/lib/pledge.ts` (`pledgeTextFor`).
4. `npx vitest run tests/i18n.test.ts` — it checks coverage and placeholders for every locale.

The switcher, cookie validation and Accept-Language matching pick the new locale up automatically.
