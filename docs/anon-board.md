# 익명 라운지 (0005)

Blind 스타일 익명 게시판. 가입을 마친, 정지되지 않은 **사람 회원만** 씁니다. AI 에이전트·MCP·CLI에는 노출하지 않습니다.

## 화면
- `/anon`: 카테고리 칩(잡담·회사생활·커리어·AI토로·고민), 최신/인기(최근 30일, 좋아요×2+답글) 정렬, 데스크톱 작성창, 모바일 FAB → `/anon/new`
- `/anon/[id]`: 스레드. 글마다 `익명의 {동물}` 별명이 붙고, 같은 스레드 안에서는 같은 사람이 같은 별명. 원글 작성자의 답글에 **글쓴이** 표시
- 좋아요 목록은 "익명 N명"만 보여줍니다(누가 눌렀는지 비공개)
- `…` 메뉴: 남의 글은 신고(사유 선택), 내 글은 삭제(답글이 있으면 "삭제된 글"로 남김)
- `/admin/anon`(운영자): 숨김/신고/전체 목록, 숨기기·숨김 해제·삭제, **사유를 적어야 하는** 작성자 조회, 운영 기록

## 개인정보 설계
- `public.anon_posts`에는 작성자 컬럼이 없습니다. anon/authenticated 역할에 테이블 권한이 전혀 없고(RLS on, 정책 없음), 모든 접근은 `anon_*` RPC로만.
- 작성자 매핑·스레드 별명·좋아요·신고·운영 기록은 API에 노출되지 않는 `anon_private` 스키마(USAGE 없음, RLS on, 권한 없음).
- RPC 응답에는 회원 id가 없습니다. 별명은 스레드마다 새로 뽑아 스레드 간 연결이 안 되고, 시간은 분 단위로 잘라 보냅니다.
- RPC는 `authenticated`에만 열려 있고 `auth.uid()`가 필요하므로 토큰 기반 MCP/CLI(anon 역할)로는 호출 불가.
- 운영자 조회(`anon_admin_trace`)는 DB에서 is_admin을 다시 확인하고, 조회자·사유를 `anon_private.moderation_log`에 남깁니다. 운영자 삭제 시에도 작성자·본문을 기록에 보존해 사후 조치가 가능합니다.

## 설정 (site_config)
| key | 기본값 |
| --- | --- |
| anon_report_hide_threshold | 5 (신고 N건이면 자동 숨김) |
| anon_daily_post_limit | 10 (하루 원글) |
| anon_daily_reply_limit | 60 (하루 답글) |
| anon_daily_report_limit | 30 (하루 신고) |
| anon_post_max_chars | 1000 |

운영자가 숨김을 해제한 글은 "검토 완료"로 표시되고, 이후 신고로는 자동 숨김되지 않습니다(운영자가 직접 다시 숨길 수 있음).
